oute-surreal-db & oute-supabase-db · plano de 2026-10-18 · branch feat/isolated-instance

1. Contexto

Cada projeto no oute-server roda num LXC com seu próprio banco embutido: SurrealDB em versões diferentes (2.6.5, 3.1.5), SQLite, Postgres. Nenhum compartilha, nenhum é padronizado, e cada um faz backup do seu jeito (ou não faz). O objetivo é consolidar em dois stacks isolados, cada um num LXC próprio, escolhendo o motor pelo que cada app realmente usa — não pelo que já está lá.

2. O que definimos

Topologia
  • LXC por stack na lxdbr0, Docker dentro — mesmo padrão dos outros projetos
  • Rede, disco e Docker próprios; sem conflito de porta 8000 entre Supabase e SurrealDB
  • Medido: containers Docker do host (inclusive a rede do agente yolo) alcançam IPs de LXC. O LXD 5.21 não aceita ACL em NIC de bridge; barreira: firewall nft dentro do LXC (só os LXCs clientes na :8000; o Docker do host chega mascarado como o IP da lxdbr0). Sem sudo. O script de ops testa o bloqueio
  • Backup = lxc snapshot / lxc export (política na F6)
  • Acesso só pela rede LXD (10.173.117.0/24)
oute-surreal-db (este repo)
  • SurrealDB v3.3.0 por digest, RocksDB, user 10001, mem 2g, cpus 1
  • Projetos: kubo, obo
  • 1 namespace por projeto; databases prd/test só onde o ambiente existe (kubo:prd,test obo:prd)
  • Por database: app_<db> OWNER (app) e ro_<db> VIEWER (backup/leitura); senhas no cofre
  • Central por propósito: novos projetos entram como namespace
  • Init idempotente; --rotate [projeto] para trocar senha
oute-supabase-db (repo próprio)
  • Compose oficial self-hosted: Postgres 17.6, Auth, PostgREST, Realtime, Storage, Edge Functions, Supavisor, Studio
  • Projetos: hanko (app próprio, já é Postgres: só troca DATABASE_URL), frentes-engenharia e financial-control (SQLite → Postgres)
  • Repo vira próprio: só docker/ + nossos arquivos, sem amarra ao upstream
  • Plano detalhado vive naquele repo
Fora do escopo
  • oute-agent — SurrealDB próprio por decisão do ADR-08 (dado derivado, isolado do agente yolo). Revisão só via ADR
  • vaultwarden — SQLite, isolado por segurança: o cofre não pode depender de um stack cujas senhas ele guarda
  • studio — projeto descontinuado
  • Dump SurrealQL agendado — depois
