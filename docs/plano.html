oute-surreal-db

SurrealDB isolado para os projetos Oute — plano de 2026-10-18 · branch feat/isolated-instance

1. Contexto

Hoje o único SurrealDB do oute-server (oute-surrealdb) pertence ao compose do oute-agent: mesma rede, mesmo ciclo de deploy, sem porta publicada. Os demais projetos (LXCs) não têm acesso a ele. O objetivo é ter uma instância própria, totalmente isolada, que sirva todos os projetos Oute com separação por namespace — e, depois, trazer para ela o conteúdo dos bancos existentes.

2. O que definimos

Instância
  • Container oute-surreal-db, SurrealDB v3.3.0 (pinada por digest), RocksDB
  • Dados em /mnt/lxd/oute-surreal-db (disco com 115 GiB livres), dono 10001:10001
  • Rede Docker própria oute-surreal-db (bridge br-oute-sdb)
  • Limites: mem 2g, cpus 1 — sem isso o RocksDB usa ~metade da RAM do host
  • Roda como user 10001 (nonroot da imagem)
Isolamento
  • Não toca no oute-surrealdb do oute-agent: nem rede, nem volume, nem alias, nem senha
  • Porta publicada só em 10.173.117.1:8000 (bridge LXD)
  • Firewall em DOCKER-USER: aceita só origem 10.173.117.0/24; container sem saída para fora
  • Sem o firewall, qualquer container Docker do host (incl. o agente "yolo") chegaria no banco
  • Regras persistem via oute-surreal-firewall.service (somem no reboot sem ele)
Modelo de dados / acesso
  • 1 namespace por projeto (hífen → underscore): obo kubo oute_agent hanko frentes_engenharia financial_control vaultgarden
  • Databases dev e prod em cada namespace
  • Usuário OWNER por database: app_dev, app_prod
  • Senhas geradas pelo init_surreal.sh, impressas uma vez, guardadas no cofre
  • Init idempotente: não toca usuário existente; --rotate [projeto] para trocar
Fora do escopo (por ora)
  • Backup — adiado; /mnt/lxd não tem backup OCI
  • Migração do conteúdo dos bancos atuais — fase 3/4, começa por kubo e obo
  • Mudanças no repo oute-agent
  • Token JWT por database (usamos usuário/senha)
  • studio — projeto descontinuado; não migra
